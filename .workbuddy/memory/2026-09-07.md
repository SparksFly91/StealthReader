- 用户要求给原本只支持 TXT 的解析流程新增 EPUB。

- 解析流程：`mimetype` 校验 → `META-INF/container.xml` 找 OPF 路径 → OPF 解析 metadata（dc:title/creator/description、EPUB2 `<meta name="cover">`）+ manifest（id→href/media-type/properties）+ spine（idref 顺序）→ 按 spine 顺序读每个 XHTML → 简易 HTML→text（block 元素加 `\n`，head/script/style 跳过，解码 `&nbsp;` 等 HTML 命名实体）→ 过滤 nav/cover/titlepage/colophon 等非正文章节 → 封面写到 `temp_dir/stealthreader/covers/{hash}.{ext}`（hash 取 href+media-type）→ 存到 `books.cover` 字段。
- `book_import` SQL 改为同步写入 cover（之前只写 title/author/introduction/file_path/total_chapters/total_chars）。
- ZIP 路径兼容 Windows/Mac：扫一遍 zip 所有名字，匹配（按 `replace('\\','/')` + trim leading `/` + 小写）；可直接 by_name 也加 `/` 前缀 兼容，避免某些 EPUB 文件名前缀差异。

### 关键踩坑（避免下次再栽）

1. **Rust 2021 prefix string 误报**：rustc 把 `xxx"..."` 视为保留前缀（参考 Rust 2021 reserved syntax）。**一旦源码中有未闭合的 string literal，后续字面量会被错位解析**为 prefix —— 报 `prefix 'image' is unknown` 同时伴随 `E0765 unterminated double quote string`。本次根因：`n.replace('\\', "/')` 误把第三个引号写成 `'`（`replace('\\', "/')` 应为 `replace('\\', "/")`），让字符串从这一行开始一直未闭合到 `properties="cover-image"` 的第一个 `"`。修复后就清爽了。
2. **`e.name().as_ref()` 的临时值问题**：`BytesStart::name()` 返回 `&QName`（借 self），`.as_ref()` 产出 `&[u8]` 也借 self。**直接在 `let name = e.name().as_ref();` 这种 statement 形式上 borrow checker 会报 E0716**：临时 `e.name()` 在 statement 结束被 drop，借用失效。两种修法：
   - `let name = e.name().as_ref().to_vec();`——堆分配但写法统一；
   - `let qname = e.name(); let name = qname.as_ref();`——零拷贝但要拆两步。
   选 `to_vec()` 更简单，后面 `name.as_slice()` 或 `name == b"..."` 都能 work（`Vec<u8>: PartialEq<&[u8; N]>`）。
3. **`File::flush` 需要 `use std::io::Write;`**——这是 trait method，不 import 看不见。
4. **`///` doc comment 后面接 `let` statement** 触发 `unused_doc_comments` 警告——doc comment 必须接 item（fn/struct/...），否则当成普通注释被 `#![warn(unused_doc_comments)]` 警告。改成 `//` 即可。
5. **`present_files`** 不需要——这次交付是功能代码（非可视成品），最终交付物就是源码改动。
6. **沙箱** —— cargo check 写 `target/debug/.fingerprint/` 等被沙箱拦了；用 Bash tool 的 `dangerouslyDisableSandbox: true` 绕过（用户首次要确认），后续同会话可继续。

## 修复 EPUB 导入 panic（UTF-8 字符边界）

- 现象：导入中文 EPUB 时 `tokio-rt-worker` panic，`epub.rs:525: start byte index 1 is not a char boundary; it is inside '第'`，前端一直卡"导入中"。
- 根因：`decode_named_entities` 里手写按字节遍历，用 `s[i..ch_end]` 按字节索引切 `&str`，i 落在多字节中文（"第"3 字节）中间就 panic。
- 修复：删除手写字节遍历 + `map_html_named_entity`，改成 `const ENTITIES` 表 + `str::replace` 逐个替换 HTML 命名实体。quick-xml 的 unescape 已处理数字实体/XML 预定义实体，这里只需兜底十几个命名实体，`str::replace` 天然按字符边界，不可能 panic。
- 教训：**处理中文/多字节文本时，绝不要用字节索引去切 `&str`**；能用 `str::replace` / `chars()` / `char_indices()` 就别手写字节游标。
- 验证：`cargo check` 通过，仅剩 3 个项目原有 warning。

## 修复 EPUB 导入卡死（O(n²) 性能陷阱）+ 遮罩溢出

- 现象：修复 UTF-8 panic 后，导入章节较多的 EPUB 仍「一直显示导入中、后台无日志」；同时全局 loading 遮罩视觉上超出窗口。
- 根因（主）：`extract_chapters` 每章调 `read_zip_text_known`，当 OPF 里 href 是相对路径（如 `chapter1.xhtml`）而 ZIP 里存 `OEBPS/chapter1.xhtml` 时 `by_name` 失败，每次都走 `resolve_entry` **遍历整个 ZIP**（`by_index` 逐条 seek+read），N 章就是 N² 次磁盘 IO，几千章的大 EPUB 直接卡到像死机，且无日志。
- 修复：`parse` 入口一次性 `build_name_index` 构建「规范化名 → 实际条目名」HashMap（normalize = 反斜杠转斜杠 + 去 leading slash + 小写），后续 `read_zip_entry`/`resolve_entry_from_index` 按 O(1) 精确匹配 + 末段后缀兜底（内存遍历，不碰磁盘）。删除旧的 `read_zip_text`/`read_zip_text_known`/`resolve_entry`，签名统一改为带 `index` 参数。O(n²) → O(n)。
- 修复（次）：`GlobalLoading.vue` 移除 `backdrop-filter: blur(2px)`（WebView2 透明无边框窗口下会渲染溢出，导致遮罩超出窗口），背景改为 rgba(0,0,0,.3) 并加 `overflow: hidden`。
- 教训：**在 ZIP/归档里按名字查找条目时，务必先建一次索引，不要每个目标都遍历全表**；尤其 EPUB 的 OPF href 几乎总是相对路径、和 ZIP 实际路径对不上，最容易踩这个 O(n²)。
- 验证：`cargo check` 通过，仅剩 3 个项目原有 warning。

## 修复 EPUB 章节标题解析（toc.ncx + title/h2 兜底）

- 现象：用户提供真实 EPUB《厂长收手吧！》（灵猫小说下载器生成，339 章 + cover + toc.ncx），章节列表标题变成 `chapter1`/`chapter2`…（fallback 到文件名），与序号对不上。
- 根因：这类 EPUB 章节标题在 `<title>` 和 `<h2>` 里（无 `<h1>`）；而 `parse_xhtml` 里 `<head>` 令 `depth_in_skip += 1`，把 `<head>` 内的 `<title>` 文本一并跳过；`extract_h1_title` 又只找 `<h1>`。于是 title/h1 都取不到，只剩 `file_stem_of`。
- 修复（epub.rs）：
  1. 新增 `parse_toc`：解析 EPUB2 的 toc.ncx，建立「规范化 src → 章节标题」映射（navLabel/text + content/src）。
  2. `OpfInfo` 加 `ncx_href`，`parse_opf` 里识别 media-type `application/x-dtbncx+xml` 记录之；`parse` 里读 toc.ncx 得到 `toc_map`。
  3. 标题优先级：toc.ncx（权威）→ XHTML `<title>` → `<h1>/<h2>/<h3>`（`extract_heading_title`，原 `extract_h1_title` 扩展）→ 文件名。
  4. 修 `parse_xhtml`：Text 分支改 `if depth_in_skip > 0 && !in_title`，让 `<title>` 文本即使位于 head 内也能被收集。
- 验证：Python 模拟修复后逻辑 → 339 章、标题 `第1章…` 到 `第339章 大结局！` 全对，0 个 fallback 到文件名；`cargo check` 通过（仅 3 个原有 warning）。
- 教训：**章节标题的权威来源是 toc.ncx（EPUB2）/ nav 文档（EPUB3），XHTML 的 title/h1 只作兜底**；且 `<title>` 在 `<head>` 内，跳过 head/style 时要排除 title。

## 修复详情页点击章节/返回报错（RouterView prevTree.el null）

- 修复（canonical，两个都上）：
  1. `src/router/index.ts` 全部路由改为**同步 import**（去掉 `() => import()`），消除懒加载/异步组件因子；副作用是 bundle 变成单个 884KB chunk（桌面应用无所谓）。
